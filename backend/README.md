# SummitMate Backend

Go + Chi + pgx + PostgreSQL 18+, OpenAPI spec-first. Design: `docs/architecture/DATA_SYNC_AUTH.md`.
Old implementation (reference only): `legacy/backend_legacy/`.

## Layout
- `api/openapi.yaml` is the contract; `api/gen.go` is generated from it.
- `migrations/000001_init_schema.up.sql` is the single schema file during initial development.
- `internal/store` is generated by sqlc from `internal/store/queries/*.sql` (auth queries only).
- `internal/auth`, `internal/sync` hold the feature code; `internal/platform` has shared infrastructure.

## Commands (run in `backend/`)
```bash
go test ./...                       # unit tests (no database needed)
go vet ./...
~/go/bin/oapi-codegen --config=api/oapi-codegen.yaml api/openapi.yaml   # or: cd api && go generate
~/go/bin/sqlc generate
```

Sync integration tests need PostgreSQL 18+ and are skipped unless `TEST_DATABASE_URL` is set:
```bash
TEST_DATABASE_URL='postgres://USER:PASS@localhost:5432/postgres?sslmode=disable' go test ./internal/sync
```

Run the server: set the variables from `.env.example`, apply the schema to an empty database with
`go run ./cmd/migrate`, then `go run ./cmd/api`. In development the email verification code is printed to the log.
